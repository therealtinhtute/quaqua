## Findings

1. **High — the branch does not compile.** `crates/quaqua/src/pipeline/mod.rs:741-755` builds `PipelineInput` without the new `base_sha` field (`pipeline/state.rs:199`; `#[serde(default)]` does not apply to struct literals). Failure: every `cargo build/test/install` on the branch dies with `error[E0063]: missing field base_sha ... --> pipeline/mod.rs:741`; no pipeline command can ship. Status: open. Evidence: test run below.

2. **High — H1 CONFIRMED: an unparseable `Verdict:` line is treated as clean.** `mod.rs:1636-1640` keeps the previous `last_findings` when `parse_verdict_str` returns Err (`if let Ok(...)`), and `mod.rs:1667-1668` then finishes `clean` when `last_findings == 0`. The watchdog only requires a line starting with `Verdict:` (`worker/prompt/watchdog.rs:83-89`), so `Verdict: not clean`, `Verdict: findings below`, or `Verdict: see above` pass it, leave `last_findings` at 0, and the pipeline reports clean with exit 0. The parser itself has a second fail-open: `mod.rs:2350-2357` returns the first integer on the line, so `Verdict: 0 of 3 findings addressed` is 0 findings → clean. The engine's fail-closed path (`parse_report_content` at `mod.rs:2364-2383`, step at `mod.rs:2214-2221`) never sees the report because this legacy branch returns through `ctx.finish` first. Status: open.

3. **High — H2 as briefed REFUTED; the underlying defect CONFIRMED: the reviewer is never bound to the gated base SHA.** The reviewer spawn `--base` is `state.head_sha` (`mod.rs:1003-1004`), which `check_impl` sets to the builder tip (`phases/mod.rs:273`) before any review, so it is not empty on the normal path. But the review prompt is built from `state.input.base` (`mod.rs:1854-1856`), the CLI `--base` branch name; `PipelineInput.base_sha` (`state.rs:199,224`) is never assigned and never read, and the gated SHA captured at builder spawn (`mod.rs:1126`; used for the size gate at `mod.rs:1513,1528`) never reaches the reviewer. Failure: with the default invocation (no `--base`, `state.base == ""` at `mod.rs:429`) the prompt reads "review only diff between base  and branch …"; the reviewer worktree is at the builder tip, so a literal `git diff` is empty → `Verdict: clean` without reviewing the change. With a moving `--base` ref, the reviewed range is not the SHA the gate approved. Status: open (the PR claim "#2 partial" does not hold for the prompt).

4. **High — the fix child loses the findings list; the builder fixes blind.** `build_fix_child` (`mod.rs:1874-1877`) uses `state.last_review_report.unwrap_or("review report")`. In the live path the engine never sets `last_review_report`: after a review with findings the legacy branch sets `state.phase = "fix"` and re-seeds the parent (`mod.rs:1736-1750`), so the replayed `ChildCompleted(review)` is dropped by the id guard (`mod.rs:2043-2046`) and `mod.rs:2106-2115` never runs. Failure: the prompt says "reviewer … reported N findings — full list in review report (readable)"; that is not a path. The old fix phase passed `<runs_dir>/<reviewer>-<task>r<round>.md` (`git show origin/quaqua/arch-integ:crates/quaqua/src/pipeline/phases/fix.rs`, prompt lines 13-21), so this is a cutover regression and a loss of the context the builder needs. Status: open.

5. **Med — the cutover leaves the old phase machine as the live decision path; the engine's report handling is dead in the CLI.** `handle_pipeline` drives every child through the transplanted plan/build/review/fix branches (`mod.rs:1439-1760`), then finishes directly (e.g. `1626,1662,1668,1677`) or re-seeds the parent (`1736`). As a result `PipelineWorkflow`'s Build/Review/Fix report handlers (`mod.rs:2086-2257`) never decide anything in the shipped path. The new tests (`mod.rs:2415-3340`) drive the workflow directly, so `test_review_with_no_verdict_fails_closed` (`3020`) can be green while the CLI fails open (#2). Failure: live-path regressions are invisible to the suite and the two rule copies drift. Status: open. Old-machine question answered: `pipeline/phases/{build,fix,plan,review,spawn}.rs` are deleted by the PR, but their logic was transplanted into `mod.rs` and is live; `phases/mod.rs` keeps `PipelineContext`, which that driver still uses.

6. **Med — two competing state sources on resume.** Each child completion seeds the engine from `pipeline-<task>.state` (`seed_state_from_pipeline_state`, `mod.rs:202-231`, used at `1736`), but the runner prefers a journal snapshot (`engine/runner.rs:412-422`) and writes periodic snapshots every 20 events (`runner.rs:1198-1211`) even though `snapshot_at_blocked` is false (`mod.rs:761-764`). Failure: once a snapshot exists the legacy seed is ignored and the otherwise-dead engine phase machine resumes instead; the two states can disagree on `phase`/`round`/`last_findings`, so `--resume` behavior depends on how many journal events a previous call happened to append (e.g. a review round re-parsed or double-counted, premature "review rounds exhausted"). Status: open; no test covers it (the resume test at `mod.rs:2698` seeds the runner directly).

7. **Low — a `.read` marker whose mtime cannot be read marks an unread report as read.** `status.rs:261-281`: `marker_valid` is `true` when the marker exists but `metadata()`/`modified()` fail (both fallback arms). Failure: on a filesystem without usable mtimes, or a permission error, an unread report is reported `Present` and WAITER-LOST is suppressed (`status.rs:305`), hiding a lost orchestrator. Status: open.
