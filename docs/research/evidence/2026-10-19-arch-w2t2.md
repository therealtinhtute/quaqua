# Summary: sude-w2t2 — Driver Support for Blocked Gate and Child Attempts

## Commit

## Changes
- **Seq-0 initial state snapshot**: On first pipeline run (`!is_resume`), driver appends seq-0 snapshot of initial state before calling `runner::run_until_blocked`, pinning replay input across resumes.
- **Count-based resume detection**: `is_plan_gate` evaluates whether `count(pause_for_approval) > count(approval_resolved)` and latest reason does not start with `blocked ` (and `parse_blocked_gate` returns `None`). Blocked gates resolve with `ApprovalResolved { approved: true, reason: Some(ResumeDirective JSON) }`.
- **Blocked gate termination**: `RunnerOutcome::Blocked` parses blocked gate via `parse_blocked_gate` and finishes with `finish(&mut state, "blocked", actual_code, Some(&reason))`, preserving code 0 for review rounds exhausted without descending into the pending-child branch.
- **Pending child counts and restart attempts**: Pending child is found by matching `started_counts[id] > done_counts[id]` from the latest `child_started` record in the journal. Attempts k >= 2 set `state.prompted = 1` so no second prompt is sent.
- **Child journal attempts (#k)**: Child journal is named `pipeline:<task>:<child_id>` for attempt 1 and `...#<k>` for attempt k >= 2. When the latest child journal is terminal with exit != 0 and no valid report is delivered, the driver advances to attempt `#<k+1>` and waits on a fresh child workflow without re-prompting.

## Answer to Unknown
In `crates/quaqua/src/pipeline/mod.rs` (lines 1214–1240), stale report archiving executes before watchdog checks if `child_report_path.is_file() && state.prompt_ts > 0 && file_mtime(&child_report_path) < state.prompt_ts`.
When a worker writes a report, its mtime is greater than or equal to `prompt_ts`. An in-place fix by an operator updates the mtime to a later timestamp (`mtime > prompt_ts`), so it is not archived. On restart, the driver sets `state.prompted = 1` and does not bump `prompt_ts`, preserving existing reports. Furthermore, `already_delivered` evaluates `validate_report_content` directly against the file on disk. A report fixed in place passes validation and is accepted immediately as `RunnerOutcome::Completed(SingleWorkerOutput::new(0, &child_report_path))` without re-prompting.
