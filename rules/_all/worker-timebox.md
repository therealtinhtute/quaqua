# Worker time budget & watchdog

- The brief's `Time budget: <N> min` line **is** the budget: `prompt-worker.sh` reads it (`PROMPT_WORKER_BUDGET_SEC` overrides when set; neither → 2700s). Check a brief before spawning: `scripts/worker/prompt-worker.sh --check-brief "<brief>"` validates its headers and prints `budget=<sec>s source=brief|env|default` (exit 1 on a bad brief). The budget is persisted in `runs/.<name>.budget`.
- `prompt-worker.sh` watches the worker while it waits for `runs/<name>.md`. Exit codes: `0` run file printed · `2` hard cap `PROMPT_WORKER_MAX_SEC` (7200) · `3` stall — no pane/worktree change for `PROMPT_WORKER_STALL_SEC` (600), agent idle/done for `PROMPT_WORKER_IDLE_SEC` (120), or agent gone · `4` time budget exceeded · `5` blocked on a question/permission · `6` malformed report (run file missing required sections such as `## Lessons`).
- At the budget deadline, if the last observed change (pane fingerprint or worktree diff) is within 2 polls, the script grants **one** grace of 25% of the budget — clamped by the cap, once per task (`runs/.<name>.grace`), printed as `WATCHDOG grace +<sec>s (progressing)`. Only then exit 4. A static pane exits 4 at the deadline.
- Budget too small for a worker that is still making progress → `prompt-worker.sh --resume <name> --extend <sec>` adds `<sec>` to that name's persisted allowance and keeps waiting (prints `WATCHDOG extend +<sec>s`). It is the only way to extend; plain `--resume` keeps the old, already-spent allowance. The cap is absolute — `--extend` past it still exits 2.
- At 80% of the budget the script sends **one** soft nudge (never again, never kills, not re-sent after an extend): wrap up, commit, write `runs/<name>.md` with a `## Blockers` section for what is left. When you see that nudge, do exactly that.
- On exit 3–5 CoS runs `herdr agent read <name> --source recent-unwrapped --lines 80` (or `--source visible` when `recent*` returns agent_not_idle), acts on what it sees, then `prompt-worker.sh --resume <name>` continues the wait. It never blind re-prompts. `blocked` can be stale — read the pane first; if it is working, just wait again.
- Long waits with no output are fine — the stall clock only measures *observable progress* (pane content or worktree diff). Keep working and it stays quiet.
- Pilots and spikes (testing an unproven tool or approach) get a 30 min budget. At 30 min with no PASS, stop: write `## Blockers` with evidence, then CoS asks the advisor once and decides keep / drop / one more timeboxed try (≤15 min). Never stack fixes on a failing pilot past the budget — 2026-10-08, srt pilot (3 stacked blockers, >30 min).
- Deadline/elapsed math in scripts must read time via the shared fake-clock hook (now_sec), never raw date +%s — 2026-10-13, runs/tieude-capfix2.md
